# 선물 마켓 데이터 (Futures Market Data) 요구사항

## 소개

BitScope에 바이낸스 Futures 공개 API를 활용한 실시간 선물 시장 지표 대시보드 기능을 추가한다. 사용자는 주요 암호화폐(BTC, ETH 등)의 롱숏 비율, 강제 청산, 미결제 약정(OI), 펀딩 비율, 탑 트레이더 롱숏 비율 등 핵심 선물 지표를 시각적으로 확인할 수 있다. 전용 페이지(`/futures`)와 크립토 데스크 위젯 두 가지 진입점을 제공한다.

---

## 요구사항

### 요구사항 1: 백엔드 - 바이낸스 Futures 데이터 수집

**사용자 스토리:** 시스템 운영자로서, 바이낸스 Futures 공개 API로부터 선물 시장 지표를 주기적으로 수집하여 프론트엔드에 제공하고 싶다.

#### 수용 기준

1. WHEN NestJS 서버가 시작되면 THEN 시스템 SHALL 바이낸스 Futures 공개 API(`https://fapi.binance.com`)로부터 다음 5가지 데이터를 수집하는 스케줄러를 초기화한다:
   - 롱숏 비율 (`/futures/data/globalLongShortAccountRatio`)
   - 강제 청산 (`/futures/data/forceOrders`)
   - 미결제 약정 (`/futures/data/openInterestHist`)
   - 펀딩 비율 (`/fapi/v1/fundingRate`)
   - 탑 트레이더 롱숏 비율 (`/futures/data/topLongShortPositionRatio`)

2. WHILE 서버가 실행 중인 동안 THEN 시스템 SHALL 1~5분 간격으로 각 지표 데이터를 polling 방식으로 수집한다.

3. WHEN 바이낸스 API로부터 데이터를 수집하면 THEN 시스템 SHALL 수집된 데이터를 인메모리 캐시에 저장한다 (DB 저장 불필요).

4. WHEN 바이낸스 API 호출이 실패하면 THEN 시스템 SHALL 에러를 로깅하고, 기존 캐시 데이터를 유지하며, 다음 polling 주기에 재시도한다.

5. WHEN 바이낸스 API가 Rate Limit 응답(429)을 반환하면 THEN 시스템 SHALL 해당 엔드포인트의 polling 간격을 일시적으로 늘리고, 경고 로그를 기록한다.

6. IF 서버가 처음 시작되어 캐시에 데이터가 없는 상태라면 THEN 시스템 SHALL 스케줄러 초기화 시 즉시 첫 데이터 수집을 수행한다.

---

### 요구사항 2: 백엔드 - REST API 제공

**사용자 스토리:** 프론트엔드 개발자로서, 수집된 선물 지표 데이터를 REST API로 조회할 수 있어야 한다.

#### 수용 기준

1. WHEN 클라이언트가 `GET /api/futures/indicators?symbol={symbol}` 요청을 보내면 THEN 시스템 SHALL 해당 심볼의 모든 선물 지표(롱숏 비율, 강제 청산, OI, 펀딩 비율, 탑 트레이더 롱숏 비율)를 통합 JSON 응답으로 반환한다.

2. WHEN 클라이언트가 `GET /api/futures/indicators/{indicatorType}?symbol={symbol}` 요청을 보내면 THEN 시스템 SHALL 해당 심볼의 특정 지표 데이터만 반환한다.

3. WHEN 클라이언트가 `GET /api/futures/symbols` 요청을 보내면 THEN 시스템 SHALL 지원하는 심볼 목록(BTC, ETH 등)을 반환한다.

4. IF 요청된 심볼이 지원 목록에 없다면 THEN 시스템 SHALL 400 Bad Request 응답과 함께 지원 가능한 심볼 목록을 반환한다.

5. IF 캐시에 해당 심볼의 데이터가 아직 없다면 THEN 시스템 SHALL 503 Service Unavailable 응답과 함께 데이터 수집 중임을 알리는 메시지를 반환한다.

6. WHEN 데이터를 반환할 때 THEN 시스템 SHALL 응답에 `lastUpdated` 타임스탬프를 포함하여 데이터의 신선도를 표시한다.

---

### 요구사항 3: 프론트엔드 - 선물 대시보드 페이지 (`/futures`)

**사용자 스토리:** 암호화폐 트레이더로서, 주요 코인의 선물 시장 지표를 한눈에 파악할 수 있는 전용 대시보드를 사용하고 싶다.

#### 수용 기준

1. WHEN 사용자가 `/futures` 경로로 접속하면 THEN 시스템 SHALL 선물 시장 지표 대시보드를 전체 화면으로 렌더링한다.

2. WHEN 대시보드가 로드되면 THEN 시스템 SHALL 기본 코인(BTC)의 선물 지표를 표시한다.

3. WHEN 사용자가 코인 선택기에서 다른 코인을 선택하면 THEN 시스템 SHALL 선택된 코인의 선물 지표로 대시보드를 갱신한다.

4. WHEN 대시보드에 지표를 표시할 때 THEN 시스템 SHALL 다음 지표를 시각화 요소로 표시한다:
   - 롱숏 비율: 게이지 차트 또는 바 차트
   - 강제 청산: 시계열 차트 또는 최근 청산 리스트
   - 미결제 약정(OI): 라인 차트 (시계열 추이)
   - 펀딩 비율: 숫자 + 양/음 색상 구분
   - 탑 트레이더 롱숏 비율: 게이지 차트 또는 바 차트

5. WHEN 대시보드가 표시될 때 THEN 시스템 SHALL 자동 슬라이드(캐러셀) 또는 탭 전환 방식으로 각 지표 간 전환을 지원한다.

6. WHEN 자동 슬라이드 모드에서 사용자가 수동으로 지표를 전환하면 THEN 시스템 SHALL 자동 슬라이드를 일시 정지하고, 일정 시간 후 다시 재개한다.

7. WHILE 대시보드가 활성화되어 있는 동안 THEN 시스템 SHALL 주기적으로 (30초~1분) 데이터를 자동 갱신한다.

---

### 요구사항 4: 프론트엔드 - 크립토 데스크 위젯

**사용자 스토리:** 크립토 데스크 사용자로서, 선택한 코인의 핵심 선물 지표를 위젯으로 요약해서 보고 싶다.

#### 수용 기준

1. WHEN 크립토 데스크(`/life`)의 위젯 선택기에서 '선물 지표' 위젯을 선택하면 THEN 시스템 SHALL 위젯 그리드에 선물 지표 요약 위젯을 추가한다.

2. WHEN 선물 지표 위젯이 렌더링되면 THEN 시스템 SHALL 선택된 코인 하나에 대해 다음 핵심 지표를 요약 표시한다:
   - 롱숏 비율 게이지
   - 펀딩 비율 (숫자)
   - 미결제 약정(OI) (숫자 또는 미니 차트)
   - 최근 청산 요약 (건수 또는 금액)

3. WHEN 사용자가 위젯 내에서 코인을 변경하면 THEN 시스템 SHALL 해당 코인의 지표로 위젯을 갱신한다.

4. WHEN 사용자가 위젯을 클릭하거나 '상세 보기' 버튼을 누르면 THEN 시스템 SHALL `/futures` 페이지로 네비게이션하여 해당 코인의 상세 지표를 표시한다.

5. WHILE 크립토 데스크 페이지가 활성화되어 있는 동안 THEN 시스템 SHALL 선물 지표 위젯의 데이터를 주기적으로 자동 갱신한다.

---

### 요구사항 5: 네비게이션 통합

**사용자 스토리:** BitScope 사용자로서, 사이드바 메뉴에서 선물 대시보드에 쉽게 접근하고 싶다.

#### 수용 기준

1. WHEN 사이드바 네비게이션이 렌더링되면 THEN 시스템 SHALL NAV_ITEMS 배열에 '선물' 메뉴 항목을 추가하여 `/futures` 경로로의 링크를 표시한다.

2. WHEN 사용자가 `/futures` 경로에 있을 때 THEN 시스템 SHALL 사이드바의 '선물' 메뉴 항목을 활성 상태로 표시한다.

3. WHEN 모바일 화면에서 하단 네비게이션이 표시될 때 THEN 시스템 SHALL '선물' 메뉴 항목을 모바일 네비게이션에도 포함한다.

---

### 요구사항 6: 지원 심볼 관리

**사용자 스토리:** 시스템 운영자로서, 선물 지표를 수집할 코인 목록을 관리하고 싶다.

#### 수용 기준

1. WHEN 시스템이 초기화되면 THEN 시스템 SHALL 기본 지원 심볼 목록(최소 BTC, ETH)을 설정한다.

2. IF 환경 변수 또는 설정 파일에 추가 심볼이 지정되어 있다면 THEN 시스템 SHALL 해당 심볼들도 데이터 수집 대상에 포함한다.

3. WHEN 새로운 심볼이 추가되면 THEN 시스템 SHALL 해당 심볼의 데이터 수집을 즉시 시작한다.

## 비기능 요구사항

### NF1: 성능

**사용자 스토리:** 사용자로서, 선물 지표 데이터를 빠르게 조회하고 싶다.

#### 수용 기준

1. WHEN 클라이언트가 선물 지표 API를 호출하면 THEN 시스템 SHALL 200ms 이내에 캐시된 데이터를 응답한다.

2. WHILE 여러 심볼의 데이터를 동시에 수집하는 동안 THEN 시스템 SHALL 바이낸스 API Rate Limit을 초과하지 않도록 요청 간격을 조절한다.

3. WHEN 프론트엔드가 대시보드를 렌더링할 때 THEN 시스템 SHALL 차트 컴포넌트를 지연 로딩(lazy loading)하여 초기 로드 성능을 최적화한다.

### NF2: 안정성

**사용자 스토리:** 사용자로서, 바이낸스 API 장애 시에도 기존에 수집된 데이터를 계속 확인할 수 있어야 한다.

#### 수용 기준

1. WHEN 바이낸스 API가 일시적으로 응답하지 않을 때 THEN 시스템 SHALL 마지막으로 성공한 캐시 데이터를 계속 제공하고, UI에 데이터 갱신 시각을 표시한다.

2. WHEN 서버가 재시작되면 THEN 시스템 SHALL 즉시 데이터 수집을 재개하여 캐시를 복구한다.

### NF3: 사용성 / 접근성

**사용자 스토리:** 사용자로서, 직관적이고 접근성 높은 UI로 선물 지표를 확인하고 싶다.

#### 수용 기준

1. WHEN 선물 대시보드 또는 위젯이 렌더링될 때 THEN 시스템 SHALL WCAG 2.1 AA 기준을 충족하는 색상 대비와 폰트 크기를 사용한다.

2. WHEN 차트/게이지에 값을 표시할 때 THEN 시스템 SHALL 양(긍정)은 초록, 음(부정)은 빨강 계열 색상을 사용하되, 색맹 사용자를 위한 추가 시각 단서(패턴, 아이콘)를 제공한다.

3. WHEN 데이터가 로딩 중일 때 THEN 시스템 SHALL 스켈레톤 UI 또는 로딩 스피너를 표시하여 사용자에게 로딩 상태를 알린다.

4. WHEN 데이터 조회에 실패하면 THEN 시스템 SHALL 사용자 친화적인 에러 메시지와 재시도 버튼을 표시한다.

### NF4: 다국어 지원

**사용자 스토리:** 사용자로서, BitScope의 기존 다국어 설정에 따라 선물 지표 UI 텍스트를 확인하고 싶다.

#### 수용 기준

1. WHEN 선물 관련 UI가 렌더링될 때 THEN 시스템 SHALL 기존 i18n 시스템(`useTranslation`)을 활용하여 한국어/영어 텍스트를 제공한다.

### NF5: 보안

**사용자 스토리:** 시스템 운영자로서, 바이낸스 공개 API 사용 시 보안 위험을 최소화하고 싶다.

#### 수용 기준

1. WHEN 바이낸스 Futures API를 호출할 때 THEN 시스템 SHALL 인증 키 없이 공개 엔드포인트만 사용한다 (사용자 개인정보 노출 위험 제거).

2. WHEN 프론트엔드가 선물 지표 데이터를 요청할 때 THEN 시스템 SHALL NestJS 백엔드를 통해서만 데이터를 제공한다 (프론트엔드에서 바이낸스 API 직접 호출 금지).
