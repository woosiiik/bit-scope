# 크립토 뉴스 피드 요구사항 문서

## 소개

BitScope 대시보드에 실시간 크립토 뉴스 피드 기능을 추가한다. CoinDesk, CoinTelegraph, The Block 등 주요 영어 크립토 미디어의 RSS 피드를 NestJS 서버에서 주기적으로 수집하고, Claude Haiku API를 활용하여 한글 요약 번역을 생성한다. 사용자는 대시보드 상단 티커(흐르는 텍스트)로 속보를 확인하고, 별도 뉴스 메뉴에서 전체 뉴스 목록을 탐색할 수 있다.

---

## 요구사항

### 요구사항 1: RSS 뉴스 수집

**사용자 스토리:** 시스템 운영자로서, 주요 크립토 미디어의 최신 뉴스를 자동으로 수집하고 싶다. 이를 통해 사용자에게 항상 최신 뉴스를 제공할 수 있다.

#### 인수 조건

1. WHEN NestJS 서버가 시작되면 THEN 시스템 SHALL RSS 수집 cron 작업을 등록한다.
2. WHILE 서버가 실행 중인 동안 THEN 시스템 SHALL 5분~10분 간격(환경변수로 설정 가능)으로 RSS 수집을 수행한다.
3. WHEN RSS 수집 cron이 실행되면 THEN 시스템 SHALL CoinDesk, CoinTelegraph, The Block 3개 소스에서 RSS 피드를 파싱한다.
4. WHEN RSS 항목이 파싱되면 THEN 시스템 SHALL 각 항목에서 제목, 본문(또는 요약), 원문 URL, 발행 시간, 소스명을 추출한다.
5. WHEN 새로운 뉴스 항목이 수집되면 THEN 시스템 SHALL 원문 URL을 기준으로 DB에 중복 여부를 확인한다.
6. IF 동일한 원문 URL이 이미 DB에 존재하면 THEN 시스템 SHALL 해당 항목을 건너뛴다.
7. WHEN RSS 소스 중 하나가 응답하지 않거나 파싱에 실패하면 THEN 시스템 SHALL 해당 소스의 오류를 로그에 기록하고 나머지 소스의 수집을 계속 진행한다.
8. WHEN RSS 수집이 완료되면 THEN 시스템 SHALL 수집 결과(신규 항목 수, 실패 소스 등)를 로그에 기록한다.

### 요구사항 2: AI 한글 요약 번역

**사용자 스토리:** BitScope 사용자로서, 영어 크립토 뉴스를 한글 요약으로 빠르게 확인하고 싶다. 이를 통해 영어에 익숙하지 않아도 핵심 내용을 파악할 수 있다.

#### 인수 조건

1. WHEN 새로운 뉴스 항목이 DB에 저장되면 THEN 시스템 SHALL Claude Haiku API를 호출하여 영어 원문을 한글로 요약 번역한다.
2. WHEN Claude Haiku API를 호출할 때 THEN 시스템 SHALL 3~5문장 분량의 한글 요약을 생성하도록 프롬프트를 구성한다.
3. WHEN 한글 요약이 생성되면 THEN 시스템 SHALL 요약 결과를 해당 뉴스 항목의 DB 레코드에 저장한다.
4. WHEN Claude API 호출이 실패하면 THEN 시스템 SHALL 오류를 로그에 기록하고 해당 항목의 요약 상태를 'failed'로 표시한다.
5. IF 요약 상태가 'failed'인 항목이 존재하면 THEN 시스템 SHALL 다음 cron 실행 시 재시도한다.
6. WHEN Claude API Key를 설정할 때 THEN 시스템 SHALL NestJS 서버의 환경변수(CLAUDE_API_KEY)에서 읽어온다.
7. WHEN 요약 번역을 생성할 때 THEN 시스템 SHALL Claude Haiku 모델을 사용하여 비용 효율을 유지한다.
8. WHEN 하루 뉴스 처리량이 100개를 초과하면 THEN 시스템 SHALL 경고 로그를 기록한다.

### 요구사항 3: 뉴스 데이터 저장 (DB)

**사용자 스토리:** 시스템 개발자로서, 뉴스 데이터를 체계적으로 저장하고 관리하고 싶다. 이를 통해 효율적인 조회와 중복 방지가 가능하다.

#### 인수 조건

1. WHEN 뉴스 엔티티를 정의할 때 THEN 시스템 SHALL 다음 필드를 포함한다: id, 원문 제목(영어), 원문 본문/요약(영어), 한글 요약, 원문 URL(unique), 소스명, 발행 시간, 요약 상태(pending/completed/failed), 생성 시간, 수정 시간.
2. WHEN 뉴스 테이블을 생성할 때 THEN 시스템 SHALL TypeORM 엔티티와 마이그레이션을 사용한다.
3. WHEN 원문 URL로 중복 체크할 때 THEN 시스템 SHALL DB의 unique 제약조건을 활용한다.
4. WHEN 뉴스를 조회할 때 THEN 시스템 SHALL 발행 시간 기준 내림차순 인덱스를 활용하여 효율적으로 조회한다.

---

### 요구사항 4: 대시보드 티커 (속보 표시)

**사용자 스토리:** BitScope 사용자로서, 대시보드에서 최신 크립토 뉴스 속보를 티커(흐르는 텍스트)로 확인하고 싶다. 이를 통해 별도 페이지 이동 없이 실시간 뉴스를 파악할 수 있다.

#### 인수 조건

1. WHEN 대시보드 페이지가 로드되면 THEN 시스템 SHALL 상단 영역에 뉴스 티커(흐르는 텍스트) 컴포넌트를 표시한다.
2. WHEN 티커가 표시될 때 THEN 시스템 SHALL 최근 뉴스의 한글 요약 제목을 좌에서 우로 흐르는 텍스트 애니메이션으로 표시한다.
3. WHEN 티커에 표시할 뉴스가 여러 개일 때 THEN 시스템 SHALL 뉴스 항목을 구분자로 구분하여 연속적으로 표시한다.
4. WHEN 사용자가 티커 위에 마우스를 올리면 THEN 시스템 SHALL 티커 애니메이션을 일시 정지한다.
5. WHEN 사용자가 티커의 뉴스 항목을 클릭하면 THEN 시스템 SHALL 뉴스 메뉴 페이지로 이동한다.
6. WHEN 요약이 완료된 뉴스가 없을 때 THEN 시스템 SHALL 티커 영역을 숨기거나 "뉴스를 불러오는 중..." 메시지를 표시한다.
7. WHEN 대시보드가 활성화되어 있는 동안 THEN 시스템 SHALL 주기적으로(예: 1분 간격) 최신 뉴스를 갱신한다.

---

### 요구사항 5: 뉴스 메뉴 페이지

**사용자 스토리:** BitScope 사용자로서, 크립토 뉴스 목록을 별도 페이지에서 상세하게 탐색하고 싶다. 이를 통해 관심 있는 뉴스를 찾아 원문을 확인할 수 있다.

#### 인수 조건

1. WHEN 사용자가 뉴스 메뉴에 접근하면 THEN 시스템 SHALL 최근 20개의 뉴스 항목을 목록으로 표시한다.
2. WHEN 각 뉴스 항목을 표시할 때 THEN 시스템 SHALL 한글 요약, 영어 원문 제목, 소스명, 발행 시간, 원문 링크를 포함한다.
3. WHEN 사용자가 "더보기" 버튼을 클릭하면 THEN 시스템 SHALL 다음 20개의 뉴스 항목을 추가로 로드한다(커서 기반 페이지네이션).
4. WHEN 사용자가 뉴스 항목의 원문 링크를 클릭하면 THEN 시스템 SHALL 새 탭에서 해당 원문 URL을 열어준다.
5. WHEN 더 이상 로드할 뉴스가 없을 때 THEN 시스템 SHALL "더보기" 버튼을 비활성화하거나 숨긴다.
6. WHEN 뉴스 목록을 로딩 중일 때 THEN 시스템 SHALL 스켈레톤 UI 또는 로딩 인디케이터를 표시한다.
7. WHEN 뉴스 목록 API 호출이 실패하면 THEN 시스템 SHALL 에러 메시지를 표시하고 재시도 버튼을 제공한다.

---

### 요구사항 6: 뉴스 API 엔드포인트

**사용자 스토리:** 프론트엔드 개발자로서, 뉴스 데이터를 조회할 수 있는 REST API가 필요하다. 이를 통해 대시보드 티커와 뉴스 목록 페이지에 데이터를 제공할 수 있다.

#### 인수 조건

1. WHEN 프론트엔드가 최신 뉴스를 요청하면 THEN 시스템 SHALL GET /api/news 엔드포인트를 통해 뉴스 목록을 반환한다.
2. WHEN 뉴스 목록 API를 호출할 때 THEN 시스템 SHALL cursor(마지막 항목 ID 또는 발행 시간)와 limit 파라미터를 지원한다.
3. WHEN limit 파라미터가 제공되지 않으면 THEN 시스템 SHALL 기본값 20개를 반환한다.
4. WHEN 뉴스 목록을 반환할 때 THEN 시스템 SHALL 요약 상태가 'completed'인 항목만 반환한다.
5. WHEN 티커용 뉴스를 요청하면 THEN 시스템 SHALL GET /api/news/ticker 엔드포인트를 통해 최근 10개의 뉴스 요약 제목을 반환한다.
6. WHEN API 응답을 구성할 때 THEN 시스템 SHALL 한글 요약, 영어 원문 제목, 소스명, 발행 시간, 원문 URL, 다음 페이지 커서 정보를 포함한다.

### 요구사항 7: 비기능 요구사항

**사용자 스토리:** 시스템 운영자로서, 뉴스 피드 기능이 안정적이고 비용 효율적으로 운영되기를 원한다. 이를 통해 서비스 품질과 운영 비용을 관리할 수 있다.

#### 인수 조건

**성능**

1. WHEN RSS 수집 cron이 실행될 때 THEN 시스템 SHALL 전체 수집 작업을 30초 이내에 완료한다.
2. WHEN 뉴스 목록 API가 호출될 때 THEN 시스템 SHALL 500ms 이내에 응답한다.
3. WHEN Claude API를 호출할 때 THEN 시스템 SHALL 개별 요약 요청에 30초 타임아웃을 설정한다.

**비용**

4. WHEN Claude Haiku API를 사용할 때 THEN 시스템 SHALL 하루 약 100개 뉴스 처리 기준으로 비용을 최적화한다.
5. WHEN API 호출 비용을 관리할 때 THEN 시스템 SHALL 불필요한 재요약(이미 완료된 항목)을 방지한다.

**안정성**

6. WHEN RSS 수집 또는 Claude API 호출에 실패하더라도 THEN 시스템 SHALL 기존 서비스(포트폴리오 조회 등)에 영향을 주지 않는다.
7. WHEN 서버가 재시작되면 THEN 시스템 SHALL 자동으로 cron 작업을 복구하고 미완료 요약을 재처리한다.

**보안**

8. WHEN Claude API Key를 관리할 때 THEN 시스템 SHALL 환경변수로만 설정하고 코드에 하드코딩하지 않는다.
9. WHEN Claude API Key를 사용할 때 THEN 시스템 SHALL 클라이언트(브라우저)에 절대 노출하지 않는다.

**운영**

10. WHEN 뉴스 수집 및 요약 작업이 실행될 때 THEN 시스템 SHALL 작업 상태와 결과를 로그로 기록하여 모니터링이 가능하도록 한다.
11. WHEN 오래된 뉴스 데이터를 관리할 때 THEN 시스템 SHALL 30일 이상 된 뉴스를 자동 삭제하는 정책을 지원한다.

## 범위 외 항목

- 뉴스 검색 기능 (키워드 검색)
- 뉴스 카테고리 분류
- 사용자별 뉴스 북마크/저장
- 한국어 뉴스 소스 추가
- 실시간 WebSocket 뉴스 푸시 (초기 버전에서는 주기적 폴링 사용)
- 뉴스 기반 감성 분석/가격 예측
